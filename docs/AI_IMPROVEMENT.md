# 学習の頭打ちに対する改善実験

更新日: 2026-10-12。

目標は平均得点だけを上げることではなく、15,000点以上を安定して得ること。比較時は平均・中央値・15,000点以上の割合・下位10%点（得点の10パーセンタイル）を併記する。「安定」の判定案は、学習やモデル選択に使用していない256 seedで15,000点以上が90%以上となること。手数上限、生成ルール、決定的な推論条件を揃える。人間の成績も同じルール・手数上限で測定できれば比較する。

2026-10-12時点のローカル記録では、探索係数0.03、隠れ層128×128、割引率0.999、得点比例報酬を約1,678万手まで試した実験がある。記録はGit対象外の`artifacts/gui/`にある。16ゲームの定期検証で最高値を選び続けた結果だけでは、未使用の盤面に強いとは判断しない。新しい入力・報酬の効果も、複数学習seedと共通の比較条件で測定する。

## 入力表現

既存の`exponents-v1`は34値。新しい`relations-v2`は以下の178値を入力する。

| 範囲（0始まり） | 内容 |
| --- | --- |
| 0〜33 | 従来の盤面・現在・予告・合成最大値・生成上限。log2の指数/32 |
| 34〜63 | 各マスの占有。空=0、ブロックあり=1 |
| 64〜93 | 現在のブロックと同じ数字か |
| 94〜123 | 予告ブロックと同じ数字か |
| 124〜147 | 横方向の隣接24組が同値か。空同士は0 |
| 148〜172 | 縦方向の隣接25組が同値か。空同士は0 |
| 173〜177 | 5列の高さ/6 |

情報はすべて公開盤面から計算する。先読み探索や、乱数状態・未表示ブロックへのアクセスは行わない。数字の上限でクリップしない。合体を保証するマスクではなく、モデルが置き方を判断するための入力である。

34値のモデルは継続利用できる。入力サイズを変更したモデルへ重みをそのまま引き継ぐことはできないので、178値は新規学習で開始する。モデルのJSONに観測形式を保存し、学習とブラウザー推論で同じ表現を使う。

## 補助報酬

`score_potential`は以下を学習報酬とする。ゲーム自体の得点は変更しない。

```
r = 得点増分/256 + κ × (γ × Φ(次の盤面) - Φ(現在の盤面))
Φ = 0.5 × 空きマス割合
  + 0.3 × (1 - 最高列の高さ/6)
  + 0.2 × (1 - 隣列の高さ差の合計/24)
```

標準のκは0.2。γはPPOの割引率と同じ値を使う。ゲームオーバーのΦは0。実験上の手数上限による打ち切りではΦを0にせず、Gymnasium/SB3のタイムアウト処理による価値の補完を使う。

盤面評価を毎手そのまま加算する方式ではなく、割引率を含む差分を加える。終了までの割引報酬に加わる総量は初期盤面に由来する一定値になるため、元の**割引された得点比例報酬**の最適方策を変えない設計である。関数近似で必ず最適方策に到達するという保証ではない。生の総得点との一致もγ<1では保証しない。

参照: [Ng・Harada・Russellの報酬変換の論文](https://people.eecs.berkeley.edu/~pabbeel/cs287-fa09/readings/NgHaradaRussell-shaping-ICML1999.pdf)。3個合体や斜め配置そのものへの罰は設けない。

## GUIでの比較

新しいプリセットを追加した。標準のネットワーク64×64、学習率0.0003、探索係数0.01、割引率0.995を共通にして、次の変更を切り分ける。

| プリセット | 入力 | 報酬 | 手数 |
| --- | --- | --- | ---: |
| 盤面特徴・対数報酬 | 178値 | 対数 | 4,194,304 |
| 盤面特徴・得点比例 | 178値 | 得点比例 | 4,194,304 |
| 盤面特徴・補助報酬 | 178値 | 得点比例＋差分 | 4,194,304 |
| 盤面特徴・補助報酬・3seed | 178値 | 得点比例＋差分 | 4,194,304×3 |

短い学習で起動と推移を確認する場合は手数を131,072〜1,048,576に変更できる。特徴だけの効果を見る場合は、従来の34値と同じ報酬・ネットワーク・学習量・学習seedで比較する。報酬を比較する場合も、入力と他の条件を揃える。探索係数などはその後に別実験で変更する。

まず入力・報酬の改善を測定する。その後も頭打ちなら、人間のリプレイによる模倣学習や、経験を再利用するDQN系などを別の学習方法として検討する。これらは今回の実装には含めない。

## 検証

同じゲーム遷移、非公開情報を使わないこと、178値モデルのPyTorch/JSON推論一致、CPython/Pyodide一致、補助報酬の終了時の差分相殺と打ち切り処理、追加学習の保存停止をテストする。

2026-10-12の短い比較では、各131,072手、学習seed 20261012、同じ16ゲーム（seed 3,000,100,000〜3,000,100,015）、上限1,000手で以下を得た。モデルは各実験の定期検証で選んだbestを使用。いずれも今回のbestは131,072手時点。

| 入力・報酬 | 平均得点 | 中央値 | 下位10%点 | 15,000点以上 |
| --- | ---: | ---: | ---: | ---: |
| 34値・得点比例 | 714.75 | 504 | 198 | 0% |
| 178値・得点比例 | 3,657.5 | 3,350 | 1,740 | 0% |
| 178値・得点比例＋補助報酬 | 2,419 | 1,894 | 1,208 | 0% |

入力と同じ得点比例報酬を使った比較では、178値が34値を上回った。この結果から次の長時間実験は「盤面特徴・得点比例」を優先する。単一学習seed・16ゲームの短い試験なので、長期の優位や統計的な有意差を確定しない。長時間実験では複数学習seedで比較し、これらの比較seedを最終評価に流用しない。[設定・モデルSHA256・ゲーム別結果](experiments/relations-pilot.json)も保存する。

今回の実装は改善を測定するための候補であり、15,000点以上の達成を確認した学習済みモデルではない。長時間・複数seedの成績を確認してから公開モデルを更新する。
