# 学習・検証GUIの使い方

更新日: 2026-10-10。WindowsのローカルPC向け。公開ゲームの配信とは独立して起動する。

## 起動と環境準備

リポジトリ直下の **`Start GUI.cmd` をダブルクリック**する。[http://127.0.0.1:8765/](http://127.0.0.1:8765/) が管理画面。すでに起動中なら同じサーバーの画面を開く。

初回のみPython 3.12以上、uv、Node.js 22.12以上を導入し、PATHを有効にする。不足する学習ライブラリや画面がある場合、「環境を準備」を押す。固定済み依存の導入と画面ビルドを実行し、完了後に画面を更新する。更新後に画面の構成を変えた場合もこのボタンで再ビルドできる。

この開発環境では依存と画面を準備済み。通常起動でコマンド入力やビルドは不要。起動で問題が出た場合のみ、診断用に次を使用できる。

```powershell
$env:PYTHONPATH = "src"
.venv/Scripts/python.exe -m drop_the_number.dashboard.server
```

起動ファイルがWindowsの実行ポリシーで止まる環境では、利用者の端末ポリシーに従う。起動処理は実行ポリシーの変更や迂回を行わない。

## 学習

プリセットは次の設定を登録している。選択すると詳細設定も標準値から入れ直す。手数欄には丸めない実際の値を表示する。

| プリセット | 1回の学習手数 | 実行数 | 通常学習との差分 |
| --- | ---: | ---: | --- |
| 動作確認 | 131,072 | 1 | 学習量のみ |
| 通常学習 | 1,048,576 | 1 | 標準設定 |
| 通常学習・3seed | 1,048,576 | 3 | 学習seedを変更して順次実行 |
| 長時間学習 | 4,194,304 | 1 | 学習量のみ |
| 長時間学習・3seed | 4,194,304 | 3 | 学習量・学習seed |
| 学習率0.0001 | 1,048,576 | 1 | 学習率0.0003→0.0001 |
| 隠れ層128,128 | 1,048,576 | 1 | 隠れ層64,64→128,128 |
| 割引率0.999 | 1,048,576 | 1 | 割引率0.995→0.999 |
| 得点比例報酬 | 1,048,576 | 1 | `log_score`→`score`（得点増分/256） |

まず通常学習・3seedで推移を確認し、改善が続く場合に長時間学習を試す。比較用の4設定は効果を検証する候補であり、性能の向上を保証するものではない。親モデルを選んだ追加学習ではプリセットを変更せず、親の設定を引き継ぐ。追加学習の手数は親の累計に追加する量。

1. 「学習」で実験名・プリセット・手数・seedを設定する。seedは画面を開いた際に自動で割り当てる。必要なら詳細設定を開く。
2. 「学習を登録」で実行またはキューへ追加する。並列環境数は一つのPPO学習内の環境数で、実験ジョブは1件ずつ実行する。
3. 一覧の「詳細」でログや内部指標を確認する。比較チェックで成績推移を重ねて表示する。得点と学習報酬は別の値。
4. 「保存して停止」はロールアウト収集・モデル更新が完了するまで待ち、更新済みモデルを保存する。定期検証の途中では完了したゲームまで記録し、途中結果から最高モデルを選ばない。
5. 保存モデルの「追加学習」で親の設定と最適化状態を引き継ぐ。手数は**追加分**。新しい実験とゲームを開始するので、中断なしの学習と同一の乱数経路にはならない。

追加学習は、親の行動・価値ネットワークと最適化状態を読み込んで更新を続ける。新規学習のように重みを初期化しない。親の保存時点から分岐した実行を別の記録へ保存し、親モデルとの比較や別の分岐を可能にする。最新モデル以外から続ける場合、親以降に行った更新は引き継がない。

追加学習の実験名は親の実験名を初期値にする。モデルの表示は「実験名 / 累計手数」で、手数や「追加学習」を名前に重ねない。過去の自動命名で長くなった名前も、親子関係を確認できるものは画面上で整理する。名前を手動変更した実験はその名前を使う。親モデルIDと実行記録IDで系統を識別する。

手数は全環境合計。PPOの更新単位に合わせるため、指定手数や保存間隔から最大1ロールアウト分だけ超えることがある。追加学習のグラフは親を含む総手数で表示する。最高モデルは完了した定期検証の平均得点で決定し、同点なら先の保存時点を維持する。

最初の完了した定期検証と同じseed・手数上限でランダムと1手先評価を一度だけ検証し、グラフの破線に表示する。基準の検証が保存されていない旧実験は基準線を表示しない。

「繰り返し比較」は同じ設定を連続した3種類の学習seedで順番に実行する。完了後の比較検証をONにすると、最高モデル・ランダム・1手先評価を既定の64ゲームで比較する。

キューの↑で順番を上げられる。待機中は「取消」。停止処理中の「強制終了」は直近の正常保存まで戻るため、保存前の更新を失う。通常は保存停止を使用する。

## 検証・比較

「モデル」で検証対象に追加し、「検証」で条件セットとモデル・比較基準を選択する。同じ条件を複数モデルに適用して登録する。

- 定期検証: 学習推移と最高モデルの選定に使用。
- 比較検証: 調整中のモデル比較に使用。
- 最終評価: 登録済み条件・学習履歴と重複しない新しいseedを使用。

条件は名前・目的・開始seed・ゲーム数・手数上限を固定する。定期検証の設定は学習設定の詳細欄にある。新しい条件の登録は学習ジョブが完了してから行う。登録済みの検証seedは学習生成から除外し、各モデルの実際のseed履歴も保存する。履歴がない取込JSONは「seed履歴不明」と表示し、未使用条件での評価とは認定しない。

検証詳細で平均・中央値・標準偏差・得点分布・手数・最大合成値・到達率・終了/上限打ち切り・推論時間を確認できる。途中で中止した結果は「途中結果」。再実行は新しい記録として残す。公平な比較には同じseed・手数上限・ルールで完了した結果を使う。

## 観戦・リプレイ・書き出し

「モデル」の「観戦」で既存ゲームを別タブで開く。モデルが自動で読み込まれ、停止状態の初期盤面を表示する。「AIを再開」「1手進む」で操作する。速度は共通ゲームのAI欄で選択する。

検証結果の代表リプレイまたはゲーム別の「再生」で、同じゲーム画面に記録を渡す。位置スライダー・1手送り・終了直前・再生/停止を使用できる。盤面を別実装で再現せず、同じエンジンで操作列を再計算する。

モデルは推論用JSON、各ゲームは共通のリプレイJSON、検証結果はJSON/CSV/HTMLとしてダウンロードできる。GUIからGitHubへの公開は行わない。JSONモデルを公開する場合は[公開手順](DEPLOYMENT.md)を使う。

「既存実験」で`artifacts/rl/`直下の`best.json`を持つ実験を取り込める。元ファイルを残して管理領域へコピーする。初期の`ppo-initial`を取り込むと学習推移とbest/latestモデルを表示できる。取込対象に存在しない途中モデル・内部指標は記録なし。学習用ZIPはこのローカル実験の保存物のみを使用し、アップロードしたZIPを実行しない。

## 保存・終了

管理情報は`artifacts/gui/manager.sqlite3`、各ジョブの設定・ログ・進捗・モデル・検証・リプレイは`artifacts/gui/runs/<ID>/`に保存する。Git対象外なので、別PCへの移行前には`artifacts/gui/`全体をバックアップする。

ブラウザーを閉じてもジョブは継続する。再接続時は既存の状態を表示し、開始要求の再送も同じ要求IDなら重複登録しない。「サーバー終了」は実行中の更新を保存して停止したあと管理サーバーを終了する。待機ジョブは次回起動まで残る。

異常終了後は実行中だったジョブを「中断」にし、正常保存済みモデルから追加学習できる。異常終了で管理サーバーだけが落ちた場合には学習子プロセスが残る可能性があるため、PC上の残存プロセスを確認してから追加学習する。失敗・ディスク不足などは詳細のログを確認する。

サーバーは`127.0.0.1`限定。スマートフォンや他PCからの管理は初期版の対象外。管理APIは起動ごとの認証、Host/Origin検査、ID経由のファイル参照を使用する。学習環境はCPU用で、並行した複数実験・GPU切替・自動パラメーター探索・完全な乱数状態の中断再開は含まない。

設計上の条件と対象範囲は[GUI_SPEC.md](GUI_SPEC.md)、CLIと観測・報酬の定義は[AI.md](AI.md)を参照。
