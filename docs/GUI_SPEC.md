# 学習・検証GUIの仕様

更新日: 2026-10-10。初期版を実装。操作手順は[GUI.md](GUI.md)。初期版の対象範囲と保存・検証の扱いをこの文書で定義する。

## 目的と起動

学習設定、開始・保存して停止・追加学習、定期検証、比較評価、モデル選択、プレイ確認、書き出しまでGUIで完結させる。日常操作でコマンド入力やJSONの手編集を要求しない。

初期対象はWindows上のローカルWebアプリ。`Start GUI.cmd`のダブルクリックで管理サーバーを起動し、ブラウザーを開く。Python環境・必要な依存・ビルド済み画面の有無を起動時に確認し、不足時にはセットアップ画面を表示する。Python 3.12以上、uv、Node.js 22.12以上の初回導入はユーザーが行い、その後の依存導入・画面ビルドはGUIの準備ボタンで実行する。Node.jsの操作を日常起動に含めない。単一exeへの梱包は初期版の対象外。

学習・検証はローカルPCで実行する。GitHub Pagesは既存のゲーム・モデル観戦、および書き出したレポートの閲覧に使用する。ブラウザーを閉じても実行中のジョブは継続し、再度GUIを開くと状態を復元する。管理サーバーを終了する操作は、ブラウザーのタブを閉じる操作と区別する。

## 画面

| 画面 | 表示・操作 |
| --- | --- |
| 実験一覧 | 実験名、状態、学習手数、経過時間、最高検証得点、日時。検索、名前変更、メモ、設定の複製、新規学習 |
| 学習設定 | 基本設定と折りたたんだ詳細設定。入力検証、設定概要、開始・キュー登録 |
| 実験詳細 | 進捗、成績グラフ、設定、保存モデル、プレイ記録、ログ。保存して停止、追加学習、検証を作成 |
| 検証管理 | 対象モデル、検証条件セット、比較AI、ゲーム数、上限手数。実行・中止、結果一覧、再実行 |
| 比較 | 複数実験・モデルの選択、成績推移の重ね合わせ、得点分布、到達率、設定差。比較条件の一致を表示 |
| モデル・プレイ | 保存時点と採用理由、観戦、リプレイの停止・1手送り・任意手への移動、モデル/記録/レポート書き出し |

セクション名は機能名にし、標語や説明と重複する状態表示は置かない。専門指標は詳細欄にまとめ、短い説明を付ける。手動のゲーム画面へ学習管理の操作を追加せず、管理GUIに集約する。

## 学習の設定と操作

基本設定は実験名、プリセット、学習手数、学習seed、学習後の自動検証。seedは自動割り当てを既定とする。

プリセット:

- 動作確認: 現在の131,072手の設定を使用。
- 通常学習: 1,048,576手。他の設定は現在のPPO設定を起点とする。
- 繰り返し比較: 同じ設定で学習seedを3種類に変えて順番に実行。

手数は全環境の合計と明記する。所要時間は実測後に目安を表示し、プリセット名から性能や完了時間を保証しない。

詳細設定は学習率、並列環境数、CPUスレッド数、ネットワーク構成、PPOの更新設定、報酬方式、1ゲームの上限手数、保存間隔、定期検証の間隔・条件・ゲーム数。初期アルゴリズムは実装済みのPPO。自然落下は常に無効。

学習開始時の設定は保存して固定する。条件を変更するときは設定を複製して新しい実験にする。

学習・検証ジョブは初期版では1件ずつ実行し、残りはキューへ登録する。複数の学習環境を使うことと、複数の実験を同時実行することを区別する。キューは順番変更・取消が可能。

「保存して停止」は更新処理の完了を待ち、モデル・最適化状態・手数・設定・seed履歴を保存して終了する。要求受理後は「停止処理中」と表示する。強制終了が必要な場合は直近の正常保存まで戻ることを表示し、正常保存済みモデルは残す。

「追加学習」は指定モデルを引き継ぐ新しい実験として作成し、親実験・元モデルを記録する。モデル構成・観測・報酬・ルールは引き継ぎ、基本操作では追加手数を指定する。ゲームは新しいエピソードから始める。中断なしの学習と完全に同じ乱数経路を再現する機能は初期版の対象外。

ブラウザーの再接続時は同じ実行ジョブを表示し、同じ開始要求の重複実行を防ぐ。管理サーバーの異常終了後は、状態を「中断」として復元し、保存済みモデルから追加学習できるようにする。

## 検証の管理

モデルを選択して条件セットを指定し、GUIから検証を実行する。最新、最高検証得点、任意の保存時点、複数モデルの一括選択に対応する。ランダムと1手先評価を比較基準として選べる。

検証条件セットは名前、seed一覧、ゲーム数、手数上限、ルール、行動の選び方を保存する。初期のモデル比較は決定的な推論を使用する。同じ条件セットを複数モデルへ適用し、再実行時も条件を固定する。

目的を以下に区別する:

- 定期検証: 学習に使わない固定seedで学習推移を確認し、最高モデルを選ぶ。
- 比較検証: モデル・設定を比較する共通の条件。繰り返し調整に使用した履歴を残す。
- 最終評価: 設定とモデルを選んだ後、新しい未使用seedで実施する。

学習用のseed割り当ては登録済みの検証・評価条件との重複を避ける。各モデルの使用seedを記録し、既存モデルや取り込んだモデルについても重複を検査する。履歴が不明なモデルは「未使用条件での評価」と認定しない。

表示する成績はゲーム得点の平均・中央値・分布、生存手数、最大合成値の分布、指定値への到達率、ゲーム終了/実験上限による打ち切りの割合、推論時間。学習報酬と実際の得点を混同しない。ゲーム数と評価条件を成績の近くへ表示する。

検証の進捗は完了ゲーム数/予定数で表示する。中止時は完了分を保存し「途中結果」と表示する。途中結果から最高モデルを自動更新しない。モデル比較は同じseedで完了したゲームを使い、比較可能な件数を表示する。

## グラフとプレイ確認

成績推移の横軸は総学習手数。経過時間への切替にも対応する。生データを保持し、平滑化表示を選べる。定期検証と最終評価を区別し、比較AIの基準線を表示する。

内部指標は行動の多様性、列の選択頻度、モデル更新量、価値予測の誤差などを詳細欄に表示する。指標に短い説明を付け、損失だけで強さを判定しない。

検証完了時に良い・悪い・中央値に近いプレイの代表記録を保存する。各ゲームのseed・モデル・得点・終了理由から選べる。保存していないゲームも、対象モデルと固定条件から再生成して結果一致を確認したうえで表示できるようにする。

観戦・リプレイの画面は、公開ゲームと同じ`index.html`・`main.ts`・`Renderer`・Worker・エンジンを使用する。GUI側にはゲームの描画・盤面遷移を重複実装しない。管理GUIが選んだモデルID・検証記録を同じローカルサーバーから自動で受け渡し、既存ゲームを別タブで開く。毎回のJSON書き出し・手動読込は不要。

観戦は停止状態から開始し、AIを再開・速度変更・1手送りできる。リプレイは停止・再開、速度、1手送り、位置スライダー、終了直前への移動に対応する。位置変更は同じエンジンで操作列を再計算する。観戦やリプレイの速度を変えても学習・検証の成績は変わらない。共通の再生操作は公開ゲームの次回ビルドにも反映される。

## 保存とモデル書き出し

実験・ジョブ・モデル・検証結果には別々のIDを付ける。設定、ルール/エンジン版、コードの版、依存版、親モデル、各seed、モデルのハッシュ、ログ、各保存時点、評価、代表リプレイを関連付ける。

モデルは保存時点ごとのファイルを残し、最新/最高を参照として管理する。初期版の最高モデルの採用基準は完了した定期検証の平均得点。採用条件・対象ゲーム数・保存時点を表示する。結果を上書きせず、検証の再実行は新しい結果として残す。

GUIから既存実験フォルダーを取り込める。現在の実験ログを表示でき、不足している内部指標や途中モデルは「記録なし」と表示する。旧ルールへ互換処理を追加しない。

「ブラウザー用モデルを書き出す」で現在の推論用JSONを保存する。モデルの取り込み、リプレイ書き出し、結果のJSON/CSV/HTMLレポート書き出しに対応する。HTMLレポートはローカルでも閲覧可能な静的成果物とする。初期版ではGUIからGitHubへ自動公開せず、既存の公開手順を使用する。

## 実装構成案

Python標準ライブラリのHTTPサーバーがGUIを配信し、ジョブ登録・進捗・保存データを管理する。学習・検証は別プロセスで既存の共通エンジンを操作する。TypeScript/Viteと既存のCanvas描画を再利用する。管理情報はSQLite、重み・履歴・リプレイは`artifacts/gui/`に保存する。公開ビルドはゲームのみ、ローカル用ビルドは管理画面と同じゲームの2入口にする。管理サーバーと学習ライブラリはPyodideの配布ソースに含めない。

管理サーバーはループバック限定。操作APIにはローカルの起動セッション認証と呼び出し元の確認を設ける。管理対象ディレクトリ内の実験IDを介して操作し、ブラウザーから任意のシェルコマンドやパスを実行させない。

進捗はおおむね1秒ごとに更新し、学習/検証/保存の段階を表示する。完了したログやモデルは一時ファイルから確定ファイルへ切り替え、保存途中のファイルをGUIへ読ませない。入力不備、ディスク不足、学習失敗、通信切断の理由と復旧操作を表示する。

学習処理へ細かなログ、保存時点ごとのチェックポイント、停止要求、追加学習を追加した。収集中のcallbackは進捗通知に使用し、保存停止はPPOの`train()`による更新完了後に処理する。更新前の収集途中でcallbackを停止する方式は採用しない。[SB3 callback API](https://stable-baselines3.readthedocs.io/en/master/guide/callbacks.html)

## 初期版の完了条件

- ダブルクリックで起動し、GUIから初回学習・保存して停止・追加学習・検証・モデル比較・観戦・書き出しまで完結する。
- ブラウザーの再読み込み・閉じて開き直す操作でジョブが重複せず、進行中の状態を復元する。
- 失敗したジョブと途中結果を正常完了と表示しない。停止や異常終了後も正常保存済みモデルを使用できる。
- GUIと直接実行で、同じモデルと検証条件の盤面・得点・終了結果が一致する。
- 学習seedの繰り返し比較、定期検証/最終評価の区別、設定・ルール・モデル由来の追跡ができる。
- 現在の学習結果を取り込み、公開ゲームと共通の画面にモデルと記録を自動で受け渡しできる。

初期版では条件セットのseedは開始値とゲーム数から連続した値を作る。保存済みの全検証ゲームを記録するため、ゲーム別の結果から直接再生できる。任意フォルダーの探索や学習用ZIPのアップロードは行わず、既存実験の取込先は`artifacts/rl/`直下に限定する。推論用JSONの取込は観戦・検証用であり、最適化状態を持たないので追加学習できない。

遠隔PCの操作、複数実験の同時実行、GPU切替、自動パラメーター探索、完全な乱数状態付き中断再開、クラウド同期、GUIからのGitHub公開は初期版の対象外とする。
