# 手動プレイ試作の起動と検証

実装版: `0.1.0`、ルール版: `prototype-v1`。ブラウザーで手動プレイできる試作。公式との全ケース比較とPagesへの実際の公開は未完了。AI学習は未実装。

## 起動

Python 3.12以上、uv、Node.js 22.12以上が必要。依存は `uv.lock` と `web/package-lock.json` で固定している。開発で使ったCPythonは3.12.7、Node.jsは22.17.0。

リポジトリのルートから:

```powershell
uv sync --frozen
cd web
npm ci
npm run dev
```

ターミナルが表示するLocal URL（通常 `http://127.0.0.1:5173/`）を開く。開発サーバーはループバック限定。スマートフォン実機からのLANアクセスを必要とする場合は、別途ホスト設定を変更する。最初の読み込みでは固定版Pyodide 314.0.7と標準ライブラリを読み込む。

## 手動プレイ

- 列のタップ・クリック、または1～5キーで投入する。左右キーで選択、Enter/Spaceで投入。Pで一時停止・再開。
- 列別の落下ボタンや常時表示の操作メッセージは設けない。エラーだけを閉じられる通知で表示する。
- 自然落下は初期OFF。ONでは3.5秒で選択列へ落ちる。切替は操作待ち状態で行い、OFF中の時間はONへ持ち越さない。
- 合体演出中の入力予約は行わない。1手を解決するまで次の投入を受け付けない。
- 一時停止・タブ非表示では自然落下を停止。タブへ戻ったら明示的に再開する。
- 通常プレイは各手の後にこのブラウザーへ自動保存。再読み込みでは停止状態で復元する。
- 記録のJSONを書き出して読み込める。読み込み後は続きから再開、または最初から手順を再生できる。
- 診断プレイは通常の保存・ベスト記録を更新しない。診断記録も明示的に書き出せる。

コイン、広告、課金、報酬画面、ハンマー、復活は実装しない。次ブロック予告は1個を常に表示する。

## 比較・診断

画面下の「比較・診断ツール」から、録画の4個合体・3個合体・最上段の救済・異値による終了を試せる。JSONを編集して任意盤面と履歴最大値を指定できる。

盤面は上から下へ6行、各行5列、数字は10進文字列、空マスは `"0"`。各列は底へ詰めて指定する。現在と予告は `current`・`next`、これまで合成した最大値は `merged_max`。履歴最大値は現在の盤面最大値と異なることがある。

`sequence` がnullならseed付き乱数、配列ならその値を今後の予告へ順に使用する。固定列が足りない手はエラーになり、盤面・得点・乱数は手の前へ戻す。現在と予告は別に指定するため、配列はその先の生成値から記入する。

実機版を再観察してから仮定を変更し、ルール版を上げる。現時点の暫定条件は次のとおり。

| 項目 | prototype-v1の採用値 | 根拠・限界 |
| --- | --- | --- |
| 盤面 | 5列×6段、最上段占有を終了条件に使う | 録画。最上段で合体して空けば救済 |
| 合体 | 下・左右の直接隣接を同時処理、m個でn×2^(m−1) | 2・4個は録画、3個はユーザー確認。連結集合全体は対象にしない仮定 |
| 連鎖起点 | 投入ブロックとその合体結果のみ | 既存ブロック起点の合体は未確認。上方向は対象にしない |
| 得点 | 各合体結果を加算、配置点なし | 観察した区間と一致。長い連鎖の例外は未検証 |
| 終了判定 | 合体→全列の重力→起点の再合体を繰り返した後 | ユーザー確認の合体後判定を採用。詳細な順序は暫定 |
| 生成 | 下限2、初期候補2・4、一様分布 | 初期・下限・分布は仮定 |
| 生成上限 | max(初期上限4, min(履歴最大値/2,128)) | 履歴による上限はユーザー確認。合体前・序盤の初期上限4を暫定的に維持 |
| 予告 | 表示済みの値を維持し、次の予告から生成上限更新 | 適用時期は仮定 |
| 進行消去 | 無効 | 閾値・対象が未確認。現行公式と差が出る可能性がある |
| 自然落下 | 3.5秒で選択列へ投入 | 手動向けの暫定時間条件。AIはOFFに固定する予定 |
| 合成最大値 | ゲーム内に固定上限を設けない | Python整数・10進文字列で転送。JSON読み込みはデータ量とビット数に検証用上限を設ける |

## 検証とビルド

ルートで:

```powershell
uv run pytest -q
```

Webディレクトリで:

```powershell
npm run test:parity
npm run build
npm run preview
```

`test:parity` は同じJSONケースをCPython 3.12とPyodideのPython 3.14で実行し、全状態・イベント・乱数状態を照合する。原作との一致とは別の確認。録画由来のケースは `tests/fixtures/official/`、ユーザー確認に基づく人工配置は `tests/fixtures/reported/` に分けている。

ビルドはPythonソースとPyodideの必要ファイルを `web/public/engine/`・`runtime/` に用意し、`web/dist/` へ出力する。ランタイム・Pythonソースはビルド生成物。画像・動画は配信しない。フォントやCDNへの実行時依存はない。

ランタイム5ファイルは合計約13.5MB（HTTP圧縮前）。Pyodide・CPythonのライセンス文と出典を `web/public/licenses/` に同梱する。ソース・ランタイムは同一ホストから取得するため、配布時は `.mjs` をJavaScript、`.wasm` を `application/wasm` として配信する。Windows標準の `python -m http.server` は端末のMIME設定によって `.mjs` が `text/plain` になることがあるので、通常の静的プレビューには `npm run preview` を使う。

Viteの相対ベースパス `./` と、起動時に渡す公開ディレクトリの絶対URLで、リポジトリ配下でもWorker・WASM・Pythonソースを取得する。公開ワークフローは[DEPLOYMENT.md](DEPLOYMENT.md)を参照。

## 制約

固定生成器は実機の乱数実装を再現したものではない。保存・リプレイの対応上限は10000手、読み込みファイルは4MB以下。エンジンは1024ビットまでのブロック値を読み込めるが、これはデータ検証の上限であり、通常合体の打ち止め条件ではない。既存の保存版が不一致なら理由を表示する。

タッチ操作用レイアウトはPCのモバイルサイズで確認し、実機のAndroid Chrome・iOS Safariの確認は別途行う。公式との完全な挙動同一性、自然落下速度、進行消去、生成分布はまだ検証完了として扱わない。
