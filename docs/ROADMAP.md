# 開発計画

更新日: 2026-10-10

## 現在の状態

- 完了: ローカルGitリポジトリ、開発方針、ルール調査台帳、比較手順、観察テンプレート。
- 未着手: 公式アプリの実機観察、ゲーム実装、依存環境の構築、AI実装。

## 第一段階: 手動プレイと公式との比較

### 1A. 仕様調査

- Android版のアプリバージョン、通常プレイのモード、端末条件を記録する。
- [ルール調査台帳](GAME_RULES.md)のP0を優先し、P1も比較完了までに調べる。
- 合体、重力、消去、終了の処理順を判別できる場面を記録する。
- 決められない仕様は未確認のまま残す。実装上の仮定を公式仕様として扱わない。

成果物: 観察記録、仕様の根拠、暫定仕様一覧。

### 1B. 手動操作できるゲーム

- 描画に依存しないゲームエンジンを作る。
- Pygameで列選択、現在・次ブロック、盤面、得点、終了、再スタートを表示する。
- 診断用に任意盤面とブロック列を読み込めるようにする。
- 落下・合体・消去を追跡できるイベント記録とリプレイを実装する。
- 通常プレイと診断用の手順実行を区別する。公式に時間進行がある場合は通常プレイで再現し、診断では停止・1手送りを可能にする。
- 未確認ルールを使用している場合、そのルールIDと設定を記録・表示する。

成果物: 起動手順、手動プレイ、診断機能、再現可能なログ、基本遷移の検証。

### 1C. 比較と修正

- [比較手順](VALIDATION.md)に沿って公式とクローンを比較する。
- 実機で観察した盤面・操作・生成値を入力し、合体後の盤面、得点、進行状態、終了状態を照合する。
- 生成分布は固定列による遷移検証と分けて評価する。
- 相違があれば観察、台帳、実装、検証用データを更新する。

第一段階の完了条件:

- 手動操作で通常プレイを開始・継続・終了・再スタートできる。
- 比較対象のバージョンとモードが明記されている。
- 対象範囲のP0・P1について検証結果があり、挙動を変える未解決の矛盾がない。
- 確定的な遷移の必須ケースがすべて一致し、観察記録に根拠をたどれる。
- 生成分布の推定条件・サンプル数・不確かさが記載されている。未知の内部乱数実装の完全一致は要求しない。
- 同じ初期状態・ルール設定・生成列・操作列でリプレイ結果が一致する。
- 確認できなかった範囲があれば「部分一致」と明記し、原作と同一と宣言しない。第二段階へ進む範囲の変更はユーザーと決める。

## 第二段階: AIの学習と評価

第一段階の比較完了後に開始する。学習中に仕様を変更する場合は、ルールのバージョンを変えて既存実験と区別する。

1. Gymnasium環境を実装し、手動プレイと同じ遷移になることを検証する。
2. ランダム配置、簡単な評価関数、先読み探索を比較基準として用意する。
3. DQN・PPOなどを比較する。行動の合法性が確定した場合に行動マスクを検討する。
4. 未使用の共通seedで得点、最大数字、生存手数、1手の計算時間を評価する。
5. 学習設定・seed・ルール版・モデル・評価結果を保存し、AIのプレイを画面で確認できるようにする。

第二段階の成果物は、学習・評価コマンド、比較基準、学習済みモデル、評価レポート、AI観戦機能。

## 初期対象外

ブースター、広告による復活、課金、広告表示、オンラインランキング、モバイル配布。対象外の機能を使用した公式プレイ記録は、基本ゲームの比較データと混ぜない。
