## 第一段階: 手動プレイと公式との比較

### 1A. 仕様調査

- Android版のアプリバージョン、通常プレイのモード、端末条件を記録する。
- [ルール調査台帳](GAME_RULES.md)のP0を優先し、P1も比較完了までに調べる。
- 合体、重力、消去、終了の処理順を判別できる場面を記録する。
- 提供されたプレイ動画があれば、[動画解析手順](VIDEO_ANALYSIS.md)でフレームとタイムスタンプから観察記録を作る。
- 決められない仕様は未確認のまま残す。実装上の仮定を公式仕様として扱わない。

成果物: 観察記録、仕様の根拠、暫定仕様一覧。

### 1B. ブラウザーで手動操作できるゲーム

- 小さな試作でPyodide Workerと共通Pythonエンジンを接続し、PC・スマートフォンの初回読み込み、再訪時の読み込み、1手の応答を測定する。満たすべき操作感と起動時間をこの測定から具体化する。
- 描画に依存しないゲームエンジンを作る。
- TypeScript・Canvas 2D・HTMLで列選択、現在・次ブロック、盤面、得点、終了、再スタートを表示する。
- マウス・キーボード・タッチ操作に対応し、PCとスマートフォンのブラウザーで遊べるようにする。
- 診断用に任意盤面とブロック列を読み込めるようにする。
- 落下・合体・消去を追跡できるイベント記録とリプレイを実装する。
- 手動プレイに自然落下オン・オフ切替を設ける。オフでも配置後の重力・合体・連鎖は解決する。診断では停止・1手送りを可能にする。
- 未確認ルールを使用している場合、そのルールIDと設定を記録し、診断パネルで確認できるようにする。
- 端末内の保存・再開とJSON形式のリプレイの読み込み・書き出しを実装する。

成果物: ローカルの開発・ビルド手順、ブラウザーの手動プレイ、診断機能、再現可能なログ、基本遷移の検証。

### 1C. 比較と修正

- [比較手順](VALIDATION.md)に沿って公式とクローンを比較する。
- 実機で観察した盤面・操作・生成値を入力し、合体後の盤面、得点、進行状態、終了状態を照合する。
- 生成分布は固定列による遷移検証と分けて評価する。
- 相違があれば観察、台帳、実装、検証用データを更新する。
- 共通検証用データをCPythonとPyodideで実行し、実行環境による差も確認する。

### 1D. GitHub Pagesへの公開

- GitHubの所有者・リポジトリ名・公開設定を決めてリモートを作成する。
- GitHub Actionsで共通エンジンを梱包し、Webをビルドして静的配布物をPagesへ公開する。
- リポジトリ配下のURLでランタイム・エンジン・Workerを取得できるか確認する。
- 公開URLでPC・スマートフォンの操作、保存、再開、リプレイを検証する。
- 詳細は[ブラウザー公開](DEPLOYMENT.md)に従う。

第一段階の完了条件:

- 公開URLを開き、PC・スマートフォンから通常プレイを開始・継続・終了・再スタートできる。
- 初回読み込みと操作応答が試作時に決めた目標を満たし、読み込み失敗時に再試行できる。
- 比較対象のバージョンとモードが明記されている。
- 対象範囲のP0・P1について検証結果があり、挙動を変える未解決の矛盾がない。
- 確定的な遷移の必須ケースがすべて一致し、観察記録に根拠をたどれる。
- 生成分布の推定条件・サンプル数・不確かさが記載されている。未知の内部乱数実装の完全一致は要求しない。
- 同じ初期状態・ルール設定・生成列・操作列でリプレイ結果が一致する。
- 同じ検証用データがCPythonとPyodideで一致する。
- 確認できなかった範囲があれば「部分一致」と明記し、原作と同一と宣言しない。第二段階へ進む範囲の変更はユーザーと決める。

## 第二段階: AIの学習と評価

ユーザーの指示で、公式との全比較が残る段階から `prototype-v2` を対象に開始した。初期実装と学習・評価は[AI.md](AI.md)に記録。学習中に仕様を変更する場合は、ルールのバージョンを変えて既存実験と区別する。

1. 自然落下なしのターン制でGymnasium環境を実装し、手動プレイの自然落下オフと同じ遷移になることを検証する。
2. ランダム配置、簡単な評価関数、先読み探索を比較基準として用意する。
3. DQN・PPOなどを比較する。行動の合法性が確定した場合に行動マスクを検討する。
4. 未使用の共通seedで得点、最大数字、生存手数、1手の計算時間を評価する。
5. 学習設定・seed・ルール版・モデル・評価結果を保存し、AIのプレイを共通リプレイとしてブラウザー画面で確認できるようにする。

第二段階の初期成果物は実装済み。ブラウザー推論にはMLPのactor重みをJSONで配布し、既存のPyodide内で実行するため、推論用の別サーバーは不要。初回PPOは1手先評価に劣っており、観測/報酬の改善・探索・複数学習seedでの性能比較は今後の実験対象。

学習・検証GUIの初期版を追加した。保存して停止・親モデルからの追加学習・複数学習seedの逐次実行・条件を固定した検証・グラフ比較・既存ゲームへのモデル/リプレイ受け渡しは[GUI.md](GUI.md)から操作できる。モデルの性能改善、観測/報酬の比較、探索は引き続き次の実験対象とする。

## 初期対象外

コイン、広告・課金と報酬画面、ブースター、復活、オンラインランキング、スマートフォンのネイティブアプリ配布。スマートフォンのブラウザー操作は第一段階に含める。次ブロック予告はゲームの情報として扱い、購入や解放処理を再現しない。予告表示の選択有無など、観測情報を変える条件は比較記録に残す。
