# プレイ動画からのルール解析

動画ファイルや読み取り可能なローカル動画からフレームを抽出し、盤面・現在ブロック・予告・得点・落下先・連鎖を時刻付きで確認できる。記録から[ルール調査台帳](GAME_RULES.md)の候補を絞り、[比較ケース](VALIDATION.md)の期待結果を作る。

現時点で動画は提供されておらず、解析済みの実機データはない。動画処理ツールも未導入。実際のファイル形式・長さを確認してから処理方法を決める。

## 動画で確認しやすい項目

| 項目 | 解析できること | 必要な場面・制約 |
| --- | --- | --- |
| 盤面・着地 | 列数、配置位置、異値の積み方 | 盤面全体と上端を映す。行容量は上端付近の場面も必要 |
| 合体 | 対象方向、値、残る位置、複数対象の扱い | 操作前後と中間フレーム。対象が多い場面を含める |
| 重力・連鎖 | 落下、再合体、処理順の候補 | 編集のない連続映像。速い演出はフレームごとに確認 |
| 得点 | 配置・合体・連鎖ごとの得点差 | 操作前後の得点が読めること。演出中と安定後を区別 |
| 進行による消去 | 発動時刻、消える数字、消去後の挙動 | 高い数字へ到達する前から記録。再到達もあるとよい |
| 終了 | 上端、満杯列、合体による救済 | ゲームオーバー直前から安定後まで |
| 時間・入力 | 自動落下、待機、入力と応答の関係 | 無操作区間とタップ表示。表示がなければ入力時刻は推定 |
| 生成 | 観察した候補値と頻度、進行段階との関係 | 多数の出現を段階別に採取。短い動画だけでは確率を確定できない |

## 動画だけでは確定できないこと

- 映っていない条件や、まだ到達していない高い数字での仕様。
- 出現しなかったブロックの確率が0か、低いだけか。
- 内部の乱数実装、seed、表示されていない進行状態。
- 結果が同じになる複数の処理方式のどれを採用しているか。
- タップ表示がない場合の、無操作と入力拒否の正確な区別。
- 欠落フレームや演出で隠れた瞬間の内部処理順。

動画から分かるのは観察した条件での挙動。1本で全ルールが確定するとは扱わず、候補が残れば追加の場面を指定する。

## 推奨する撮影条件

- MP4などの画面録画を、可能なら元ファイルのまま用意する。
- 盤面全体、上端、現在・次ブロック、得点を常に入れる。
- 数字が読める解像度で撮影する。目安は720p以上、30fps以上。速い連鎖を調べるなら60fpsが望ましいが、読み取り可能性は実際の映像で判断する。
- 倍速、途中のカット、フレーム補間を行わない。編集した場合は元の時刻との対応を添える。
- 可能ならタップ位置の表示を有効にする。タップ表示なしでも盤面遷移の確認はできる。
- アプリのバージョン・モードを添える。最初からの連続録画があると進行履歴を追いやすい。
- 通常プレイの比較ではブースターと復活を使わない。使用した場面は別に記録する。

音声は必須ではない。長い映像では確認したい場面の時刻を添えると解析を絞りやすい。

## 最初に欲しい場面

1. 新規開始からの通常プレイを1～3分程度。基本合体、横方向、予告、得点を確認する。
2. 下と左右に同じ数字がある場面、同値3個・4個が接する場面。
3. 合体で空いた場所へ既存ブロックが落ち、さらに連鎖する場面。
4. 高い数字の達成前後で、小さい数字が消える場面。可能なら同じ高い数字を再度作る。
5. 上端に近い状態からの合体やゲームオーバー。
6. 無操作で待つ場面、一時停止・再開する場面。

すべてを最初からそろえる必要はない。通常プレイの動画から先に解析し、足りない比較ケースだけを追加収集する。各場面は操作の数秒前から結果が安定するまでを含める。

## 解析の進め方

1. 原本を `evidence/raw/` に置き、ファイルのハッシュと映像の長さ・解像度・フレームレートを記録する。
2. 全体を粗い間隔で確認して操作・合体・消去・終了の候補区間を絞る。
3. 該当区間をフレーム単位で抽出し、原本のタイムスタンプを付けて `evidence/derived/` に保存する。可変フレームレートでは単純なフレーム番号÷fpsで時刻を決めない。
4. 操作前後の盤面、現在・予告、得点を読み取る。OCRは候補抽出に使えるが、採用する値は該当画像でも確認する。
5. 中間フレームを調べ、処理順を候補ごとに比較する。ぼやけた値や演出に隠れたマスは不明と記録する。
6. [観察テンプレート](observations/TEMPLATE.md)で1ケースずつ保存し、直接観察と推定を分ける。
7. 確認できた仕様を台帳へ反映し、公式由来の検証用データに変換する。
8. クローンへ同じ状態・操作・生成列を与え、結果を比較する。

成果物は、時刻付きの観察記録、確認できたルール、残る候補、追加収集する場面、検証用データ。動画の解析はローカルで行う方針で、ブラウザーの公開ゲームに動画アップロード機能は追加しない。
