# OBS-0002: 下・左・右を含む4個合体と重力

観察日: 2026-10-10 JST。動画観察済み、記録した連鎖の盤面・得点・合体値はクローンと一致。撮影条件・原本・ハッシュは[VIDEO-0001](VIDEO-0001-short-play.md)を参照。関連: R05～R13・R24・R25、V07・V09～V11・V18。

## 操作と中間結果

直前に第2列へ4を投入して4同士が8になった。40秒はその後の連鎖中で、入力を受け付ける安定状態とは限らない。以下は下から上への列スタック。

```text
t=40.00秒
列1: [32,16,64]
列2: [16,8,8]  # 上の8が合体の起点
列3: [8,16]
列4: [2]
列5: [8]
得点表示:164、予告:2
```

| 抽出時刻 | 中間状態 |
| --- | --- |
| 40.25秒 | 第2列の8同士が16に合体。得点表示175は増加演出の途中 |
| 40.50秒 | 新しい16が下がり、下・左・右の16に接する。得点表示180 = 164+16 |
| 40.75秒 | 新しい128を表示。周囲の16が消費される。得点表示287は増加演出の途中 |
| 41.00秒 | 第2列の128が底へ落ち、第1列の64も下へ詰まる。得点308 |

```text
t=41.00秒（連鎖後）
列1: [32,64]
列2: [128]
列3: [8]
列4: [2]
列5: [8]
得点:308、予告:2
```

4個の16から128ができる。単純総和64でも、1組だけを合体して残りを残す結果でもない。得点差144は、16の生成と128の生成の加算 `16+128` に一致する。

根拠: `evidence/derived/short-video/t40.jpg`・`t40.25.jpg`・`t40.5.jpg`・`t40.75.jpg`・`t41.jpg`。一覧 `four-tile.jpg`。時刻はシーク指定値であり、内部処理の厳密な発火時刻ではない。

## 解釈と限界

この配置で下・左・右の同値をまとめて取り込む挙動、起点が残る位置、合体後の重力と再判定を動画観察した。隣接対象k個ごとに倍増する `n×2^k` は候補。3個合体、上方向、連結集合全体、異なる配置の優先順は未確定。既存64が落ちることは確認できるが、その既存ブロックの再合体の有無はこの場面では判別できない。

得点のアニメーション途中の175・287をゲームの加点式に使わない。fixtureでは先行する4の投入前（得点156）まで状態をさかのぼり、4→8→16→128の連鎖全体を比較する。得点差は152（8+16+128）。
