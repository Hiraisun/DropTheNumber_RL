# 観察記録

現在、提供された短い録画の動画観察は3件。転記した3場面の配置・盤面・得点・合体値・終了をクローンと比較し、その範囲で一致。対象バージョンを固定した直接の実機検証は0件。[録画の調査結果](VIDEO-0001-short-play.md)に資料・方法・未確定仕様をまとめた。公式ページの調査は[ゲームルール調査台帳](../GAME_RULES.md)を参照。

別途、[ユーザーの仕様補足](USER-0001-rule-clarifications.md)を1件記録。3個合体・斜め除外・最上段救済・生成上限はユーザー確認、均等分布・上方向なし・合成上限なしは推定として区別する。

[足場消失後の落下合体の不具合報告](USER-0002-fallen-merges.md)を反映し、prototype-v2では落下した既存ブロックも合体の起点にする。人工配置4件で回帰確認。複数起点の公式の処理順は未確認。

## 記録の作成

1. [TEMPLATE.md](TEMPLATE.md)を複製し、`OBS-0001-short-description.md` のように保存する。
2. 比較対象版、関連ルールID、比較ケース、操作前後の状態、根拠を記入する。
3. 1件の観察と、そこから考えた仕様の推定を分けて書く。
4. 同じ条件での再観察、反例、別の候補を排除できたかを記録する。
5. 台帳に結果と観察IDを追記する。未確認の仕様を文書上だけで確定しない。

書面の観察記録と期待結果はGitで管理する。動画・画像を保存する場合はローカルの `evidence/raw/` を使い、ファイル名・SHA-256・該当時刻を記録に残す。原本を参照できない場合はその制約を明記する。

提供動画からの観察は[プレイ動画の解析](../VIDEO_ANALYSIS.md)に従う。抽出フレームやOCR候補は `evidence/derived/` に置き、原本の時刻との対応を記録する。撮影者と解析者を分け、読み取れなかったマスや入力時刻は不明とする。
