# USER-0002: 足場消失後の落下合体

記録日: 2026-10-10 JST。出典: この会話のユーザーによる不具合報告。特定の盤面・動画時刻は未提供。

「他の数字の合体により足場が消えて落下した際に、合体判定が行われていないよう」と報告された。prototype-v1は投入ブロックとその合体結果だけを判定しており、落下した既存ブロックを判定対象に含めていなかった。

prototype-v2では重力で移動したブロックも起点に含める。合体結果の続き、既に待機中の起点、新たに落下した起点の順に解決する。新たな落下起点は下段から上段、同じ段では左から右。合体で消費された起点は除き、重力で移動した起点の座標を更新する。下・左右の同値を同時合体し、上・斜めは対象にしない。

この処理順は決定的な実装のための暫定選択であり、公式の順序を映像で確認したものではない。移動・合体に無関係な既存ブロックは全盤面走査で自動合体させない。

`tests/fixtures/regressions/` の人工配置で確認する（実機映像の観察とは区別）:

- `fallen-vertical`: 足場16の消失後、8が8の上に落下して16になる。合計加点48。
- `fallen-horizontal-chain`: 落下した8が左の8と合体して16、その下の16と再合体して32。合計加点80。
- `fallen-both-sides`: 左右2列の足場が消失し、投入ブロック以外の列でも落下合体する。合計加点80。
- `fallen-pending-remap`: 上段の待機中ブロックが追加の重力で再移動し、下・右の32を同時合体して128。合計加点208。

ユーザー指定により旧版との互換は不要。prototype-v1の保存・リプレイは読み込まない。仕様台帳のR12・R13に反映。
